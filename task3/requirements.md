# Список требований, которым должны удовлетворить внешние интеграции
## Требования к безопасности
При взаимодействии через внешние интеграции с партнерами и гос. платформами передаются важные данные о клиентах, такие как персональные данные, биометрия. Соответственно важно уделить внимание целостности данных и их защите от утечек:
* между терминальными системами должен быть установлен приватный канал с использованием VPN
* транспортное шифрование TLS (версия 1.2 или 1.3)
* все запросы должны быть аутентифицированы, у субъекта-источника должны быть права на действия с объектом. Для этого требуется использовать OAuth 2.0 с передачей по защищенным протоколам JWT токенов, имеющих ограниченный срок жизни
* следование принципу минимальных привилегий - права выдаются только на то, что нужно для работы бизнес-процесса

Поскольку на основании данных, получаемых из внешних интеграций, принимается решение об отправке на устройства критичных управляющих команд, таких как "открыть дверь", важно защититься от подмены данных:
* контроль целостности сообщений с использованием хеширования HMAC

Чтобы избежать утечек из-за случайных или намеренных ошибок в конфигурации инфраструктуры:
* входящий/исходящий траффик должен идти через firewall
* должен быть настроен белый список ip-адресов для входящих/исходящих подключений

Также, т.к. предугадать все возможные сценарии атак невозможно, важно настроить адекватный мониторинг, в том числе детектирующий аномалии во взаимодействии с внешними API:
* внедрить систему мониторинга безопасности (SIEM) и настроить автоматические оповещения при обнаружении аномалий
* мониторить сетевую активность и настроить автоматические оповещения при выявлении подозрительного траффика
* контролировать изменения конфигураций и настроить автоматические оповещения, если они производятся непланово
* регулярно сканировать инфраструктуру на наличие уязвимостей

Дополнительно стоит защищать данные при хранении:
- биометрия и др. перс данные клиентов должны храниться в шифрованном виде
- номера автомобилей должны храниться в виде токенов

## Протоколы аутентификации и авторизации
* HTTPS (TLS 1.2 или 1.3)
* OAuth 2.0

## Организация взаимодействия между системами предприятия и внешней платформой
Основные моменты:
* между системами установлено безопасное соединение через VPN;
* взаимодействие с использованием REST API по протоколу HTTPs (TLS 1.2 или 1.3);
* входящие и исходящие потоки взаимодействия проходят через firewall, ограничены белыми списками ip адресов и логируются соответствующим образом для последующего анализа и мониторинга;
* для аутентификации и авторизации запросов используется OAuth 2.0 с jwt-токенами, генерируемых отдельным auth-server;

Также важно заложить в бизнес-логике ролевую модель, ограничивающую доступ к данным и управление устройствами:
* собственник видит только свой устройства и может управлять ими
* менеджер видит все устройства своих клиентов

Доступ менеджеров к чувствительной информации клиентов должен логироваться в журнале для последующего анализа и мониторинга
